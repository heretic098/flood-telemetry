## 1. Visual Hierarchy & Card Design

During flood events, non-technical residents need rapid, scannable clarity without needing to interpret raw hydrological tables or Ordnance Datum elevations. The status card architecture prioritizes plain-English status first, followed by supporting telemetry and ground-truth verification.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│  LOCATION / ASSET TITLE                     [ 🔴 OVERSPILLING ] Pill          │
│  River Tone at Hookbridge Spillway          Updated: 14 mins ago             │
├──────────────────────────────────────────────────────────────────────────────┤
│  PRIMARY HERO METRIC:                                                        │
│  7.62 m AOD  /  7.45 m Crest                Overtopping by +0.17 m          │
│  [========================================|||||||] Progress Clearance Bar    │
├──────────────────────────────────────────────────────────────────────────────┤
│  SECONDARY METRICS GRID:                                                     │
│  ⏱️ Duration: 04h 12m                       🌊 Est. Flow: ~14.2 m³/s          │
├──────────────────────────────────────────────────────────────────────────────┤
│  📷 GROUND-TRUTH AI VISION VERIFICATION:                                     │
│  [ Thumbnail Image ]  "Webcam confirms water flowing over Hookbridge crest.  │
│                       Debris clear near gauge."                             │
│                       Badge: [🤖 AI Verified | 94% Confidence | Daylight]    │
└──────────────────────────────────────────────────────────────────────────────┘
```

### Key Card Layout Principles:

1. **Card Header:**
   - Plain-English location title (e.g., *Hookbridge Spillway — River Tone to Curry Moor*).
   - High-contrast Status Token Pill anchored top-right.
   - Relative timestamp (*"Updated 4 mins ago"*) to build trust in freshness.

2. **Hero Stage & Clearance Metric:**
   - Prominent numerical stage display using monospace/tabular numbers (`7.62 m AOD`).
   - Comparison against engineered crest height (`7.45 m Crest`).
   - Dynamic **Clearance / Overtopping Delta Badge**:
     - Below crest: Green background (`+0.25 m clearance below crest`).
     - Overtopping: Red high-contrast background with bold directional indicator (`▲ Overtopping by +0.17 m`).
   - Visual **Clearance Progress Bar**: A horizontal gauge showing water level relative to crest height, turning red when exceeding 100%.

3. **Secondary Hydrological Context:**
   - **Continuous Spill Duration Counter**: Displayed prominently when active (`⏱️ Duration: 04h 12m`).
   - **Estimated Flow Rate**: Clear rate display (`🌊 ~14.2 m³/s`) with plain-English context tooltip (*"Moderate overwash into Curry Moor storage basin"*).

4. **AI Vision Verification Badge & Ground-Truth Strip:**
   - **Visual Badge**: Integrated `[ 🤖 AI Ground-Truth Verified ]` badge with confidence level (`High / 94%`) and lighting status (`Daylight`).
   - **Webcam Thumbnail**: Clickable image preview expanding to a full light-box modal with original resolution.
   - **AI Visual Summary**: One-sentence plain-English description generated by Gemini Flash (*"Camera confirms turbid water overtopping spillway crest into Curry Moor"*).
   - **Fallback State**: If API key is unavailable or night illumination is low, fallback badge shows `[ 📷 Live Camera Feed (Telemetry Active) ]` without broken UI states.

5. **Monk's Leaze Clyse (Sluice Structure) Special Card Design:**
   - Dual-level comparison: **Upstream Level** vs **Downstream Level** with head differential ($\Delta h$).
   - Flow Direction Banner: Prominent indicator showing water being actively diverted from the Parrett into the Sowy Relief Channel (`River Parrett ── 🔵 DIVERTING ──> Sowy Channel`).

## 2. Color-Blind Accessible Status Tokens

To comply with **WCAG 2.1 AA** accessibility guidelines and accommodate residents with color-vision deficiencies (Protanopia, Deuteranopia, Tritanopia, Monochromacy), status tokens MUST NEVER rely on color alone. Every status uses a **Triple-Encoding Architecture**:

$$\text{Status Token} = \text{Distinct Icon Symbol} + \text{High-Contrast Background/Text Color} + \text{Explicit Uppercase Label}$$

### Standardized Status Token Matrix

### 5.2 Real-Time Telemetry Updates (`aria-live="polite"`)

Telemetry updates fetched during the 15-minute background sync MUST announce state changes smoothly without interrupting the user's focus:

- **Telemetry Value Containers:** Wrapped in `aria-live="polite"` and `aria-atomic="true"`. Screen readers announce updated numbers (e.g. stage height or duration) when the values change.
- **Critical Status Escalations:** The global emergency status banner uses `aria-live="assertive"` so that if a spillway transition changes from `🟢 SECURE` to `🔴 OVERSPILLING`, screen reader users receive immediate priority alerts.

---

### 5.3 Accessible Icon & Emoji Wrapper Pattern (`aria-hidden="true"` + `.sr-only`)

Emojis used for visual status indicators (🟢, 🔴, 🔵, ⛔, ⏱️, 🌊, 🤖, 📷) can result in noisy screen reader output (e.g. reading *"Large Red Circle Button"* or *"Water Wave"*).

**Required Wrapping Pattern:**
1. Hide the raw emoji symbol from screen readers: `<span aria-hidden="true">🔴</span>`
2. Provide explicit textual screen-reader context using CSS utility class `.sr-only`: `<span class="sr-only">Current Status: Overspilling</span>`

#### CSS Specification for Screen Reader Only Class:
```css
/* Standard WCAG-compliant Accessible Screen Reader Hiding Utility */
.sr-only {
  position: absolute !important;
  width: 1px !important;
  height: 1px !important;
  padding: 0 !important;
  margin: -1px !important;
  overflow: hidden !important;
  clip: rect(0, 0, 0, 0) !important;
  white-space: nowrap !important;
  border-width: 0 !important;
}
```

## 6. Telemetry Freshness Thresholds & Unified Badge Classification System

To prevent false alarms and align with real-world Environment Agency (EA) telemetry operational cadences, the dashboard implements a unified 3-tier telemetry freshness classification across all UI components (Header Status Pill, Database Sync Drawer, Station Matrix Table, and Card Tooltips).

### 6.1 EA Telemetry Transmission Context

Environment Agency rural telemetry stations operate under variable transmission regimes:
- **Active High-Flow / Flood Alerts:** Telemetry is transmitted rapidly at **15-minute to 60-minute** intervals.
- **Normal / Low-Flow Regimes:** Telemetry stations transmit routinely every **2 to 6 hours** to conserve power and satellite bandwidth.

Previous thresholds marked gauges as `🔴 STALE` after only 1–2 hours of inactivity, causing unnecessary resident anxiety. The unified 3-tier system aligns user expectations with EA operational norms while still flagging genuine station outages.

---

### 6.2 Standardized 3-Tier Freshness Matrix

| Tier State | Age Threshold ($\Delta t$) | Badge Class | Color Tokens (Light / Dark) | Text Label | Accessibility String (`.sr-only`) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 🟢 **FRESH / NOMINAL** | $\le 120\text{ mins}$ ($\le 2\text{ hours}$) | `.freshness-fresh` | Text `#064E3B` / `#6EE7B7`<br>Bg `#D1FAE5` / `#064E3B`<br>Border `#A7F3D0` / `#059669` | `🟢 FRESH (<2h)` | `Telemetry status: Fresh (reading received within the last 2 hours)` |
| 🟡 **LAGGING / DELAYED** | $> 120\text{ mins}$ and $\le 360\text{ mins}$ ($2\text{–}6\text{ hours}$) | `.freshness-warning` | Text `#78350F` / `#FDE68A`<br>Bg `#FEF3C7` / `#78350F`<br>Border `#FDE68A` / `#D97706` | `🟡 LAGGING (2-6h)` | `Telemetry status: Lagging (reading delayed between 2 to 6 hours ago)` |
| 🔴 **STALE / OFFLINE** | $> 360\text{ mins}$ ($> 6\text{ hours}$) | `.freshness-stale` | Text `#7F1D1D` / `#FCA5A5`<br>Bg `#FEE2E2` / `#7F1D1D`<br>Border `#FCA5A5` / `#DC2626` | `🔴 STALE (>6h)` | `Telemetry status: Stale (no reading received for over 6 hours)` |

## 8. Moor-Centric Container Card Architecture with Top Hero Control Banners

### 8.1 The UX Dilemma & Architectural Solution

**Resident Mental Model:** Local residents think in terms of **their Moor / Polder Basin** (e.g. *"Is Curry Moor flooding?"*, *"What's happening at Northmoor?"*, *"Is Dunball tide-locked?"*). Therefore, the primary organizational container cards MUST remain Moor-centric (Curry Moor, Northmoor, Sowy / Monk's Leaze, Dunball Outfall).

**The Overtopping Hierarchy Problem:** Previously, critical spillway overtopping states (Hookbridge Spillway, Baltmoor Wall) and clyse diversion states were buried inside minor text bullet points inside the card.

**The Solution — Moor Container + Top Hero Control Banner:**
Each Moor Card functions as the primary container, but its **VERY FIRST / TOP ELEMENT** inside the card body is a **Prominent Top Hero Spillway / Control Status Banner**.

## 9. Multi-Page Information Architecture & Dedicated Topology View (`topology.html`)

### 9.1 UX Evaluation & Trade-Off Analysis

**The Challenge:** Should the River Network Topology Schematic be embedded at the bottom of the main dashboard (`index.html`) or moved to a dedicated page (`topology.html`)?

| Architecture Option | UX Pros | UX Cons | Recommendation |
| :--- | :--- | :--- | :--- |
| **Option A: Embedded at Bottom of `index.html`** | Single page URL for everything; no page transition needed. | • Severe vertical page bloat on mobile.<br>• Touch gesture conflicts (panning/zooming SVG map vs page scrolling).<br>• Clutters emergency dashboard for residents who only want quick Moor card answers. | ❌ **Rejected** |
| **Option B: Dedicated Page (`topology.html`)** | • Keeps `index.html` ultra-clean, scannable, and 100% focused on Moor Cards.<br>• Full-screen interactive SVG canvas on `topology.html` with side-by-side node inspector drawer.<br>• Zero mobile scroll/touch conflicts. | Requires explicit top navigation bar link. | ✅ **APPROVED** |

**UX Decision:** Move the River Network Topology Schematic to a dedicated page (`topology.html`). The main dashboard (`index.html`) remains laser-focused on the 4 Moor Cards and Top Hero Control Banners.
